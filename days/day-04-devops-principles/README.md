## Goal

Understand **CALMS** and **DORA** well enough to explain them without a slide. No Azure spend today.

## High-level architecture (summary)

Open **[handout.pdf](./handout.pdf)** for tables. Short version:

| Model | What it is |
|-------|------------|
| **CALMS** | Culture, Automation, Lean, Measurement, Sharing |
| **DORA** | Deployment frequency, lead time, change failure rate, time to restore |
| **DevOps** | Habits + outcomes — not a job title |

**One-liner:** CALMS = what good feels like. DORA = how you prove it. Tools without habits = theatre.

## Learn

- [Using the four keys to measure DevOps performance](https://cloud.google.com/blog/products/devops-sre/using-the-four-keys-to-measure-your-devops-performance)

## Step-by-step lab

1. Score yourself (or last team) **1–5** on each CALMS letter.
2. Circle the weakest letter.
3. Pick **one** DORA metric you can measure later on a personal lab.
4. Write three sentences: what “good” looks like for that metric in six months.

## Done when

- [ ] You can explain CALMS without reading a slide  
- [ ] You can name the four DORA metrics  
- [ ] You filled a scorecard and picked one metric to track
